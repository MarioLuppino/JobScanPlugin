# Work Search Log

**Use this if you are claiming unemployment benefits.** Most programs require a minimum number of
documented job-search activities per week, and the documentation is your responsibility. This is the
running record.

**Verify the actual requirement yourself, with the agency that pays you.** The number of required
activities, what counts as one, what evidence you must keep, how long you must keep it, and the exact
week boundary all vary by state and country and change over time. A benefit week that runs Sunday–Saturday
versus Monday–Sunday shifts your deadline by a day, which is enough to miss it. **This file is a
record-keeping aid, not guidance on eligibility.**

## How this connects to the scan

When a weekly quota is in play, it changes what the scan is *for*. Finding ten beautifully ranked
candidates is worthless if none of them are ones you can actually apply to this week.

- Tell the `job-search` skill your quota. Its job becomes surfacing **enough genuinely applyable roles to
  clear that number every week**, and a scan that surfaces fewer has failed at its primary function.
- **Never let a quota lower the bar.** The right response to a thin week is a wider sweep — more sources,
  more search terms — not a lower fit floor and never a padded list. If the roles genuinely aren't there,
  the scan should say so plainly, because that is actionable and a padded list is not.
- **A prepared packet does not count. Only a submitted application does**, and you submit it — this system
  prepares packets and never submits on your behalf.
- Log the application the day it goes out, then append the packet row to `Applied Index.md` as usual.
  `Applied Index.md` tracks packets and outcomes; this file tracks benefit-qualifying activity. They are
  different records and you want both.
