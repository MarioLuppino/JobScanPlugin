# Résumé formats & ATS strategy

One document does not fit all role types. Match the résumé to the screening system *and* the human who reads
after it. Keep the master profile as the source of truth; generate the right derivative per application.

## The "AI screens it anyway, so send everything" trap

Partly true, mostly risky. ATS/AI screeners rank by *relevance* to the specific posting. A 10-page
everything-CV can *lower* your match score by diluting relevant terms among irrelevant ones, and it signals
weak prioritization to the human reviewer. Comprehensive helps only when the format is machine-readable and
the content is aimed at the posting. **So: tailor to the target, and make it ATS-safe.**

## Tiers (produce the right derivative)

1. **Master CV** — comprehensive; used directly for **academic/research** roles where a full CV is expected.
2. **Federal / government résumé** — long and detailed is *correct*. HR scores against the announcement's
   "specialized experience," often checking for mirrored language. Include month/year **and** hours-per-week
   per position, supervisor + "may we contact," salary/grade if asked, and duty bullets that echo the
   announcement's keywords/KSAs almost verbatim. Routinely 4–6+ pages.
3. **Tailored 1–2 page** — for **industry, consulting, sales, and most state-agency** roles. Lead with
   quantified achievements, not duties. Cut minutiae (full publication lists, every outreach event). Mirror
   the posting's hard skills exactly — but only the ones genuinely held; name ramp-up skills honestly, never
   as claims.
4. **State agency (2–4 pp) + the online form** — NEOGOV-style portals weight the structured fields and the
   explicit required/preferred qualifications heavily. Answer each qualification directly in the form; the
   résumé + cover letter + references round it out.

## ATS-safe formatting rules (every non-academic derivative)

- **Single column.** No tables, text boxes, or multi-column layouts for parsed content.
- **Standard headings:** Summary, Skills, Professional Experience, Education, Certifications, Publications.
- **No critical content in headers/footers or images** — many parsers ignore them. Keep name/contact in the
  body.
- **Standard fonts, black text, simple bullets.** No icons/graphics. Respect any minimum font size the user
  set in onboarding.
- **Keywords in context**, mirroring the posting's exact terms where they're true. No white-text stuffing —
  screeners and humans both penalize it.
- **File type:** submit `.docx` unless the posting requires PDF; if PDF, export a text-based (not scanned)
  PDF. Where a portal has its own form, fill the fields fully.

## Production

Draft/tailor in Markdown, then produce an ATS-safe Word file with the `docx` skill, using the single-column,
standard-heading rules above. The user opens and edits it in Microsoft Word or Apple Pages; if a portal wants
PDF, they export one from there (see `docx-generation.md`). Keep the tailored
derivative in the application's numbered folder alongside its cover letter.
